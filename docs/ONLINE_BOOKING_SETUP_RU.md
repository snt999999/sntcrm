# СОЛНЦАНЕТ — собственная онлайн-запись (версия 1)

## Что входит

- Страница `/zapis.html` вместо Cal.com: Архитектура → Замер/Монтаж, Авто → услуга; дата, время, контакты, вложения.
- Публичный каталог услуг, подготавливаемый из действующего справочника CRM. Длительности **не придуманы**; все услуги в начале выключены. Цены `от` взяты из существующей CRM, их следует проверить.
- Пн–Пт 09:00–18:00 (Екатеринбург), со следующего дня на 30 дней, длительность/шаг по услуге, 2 одновременных места в каждом направлении. Слоты учитывают существующие заявки и ручные блокировки CRM, но **не** ручные события Google Calendar.
- Заявка в старой CRM, статус «Ожидает подтверждения», источник «С сайта», резерв до 24 часов. Уведомления в личный Telegram Сергея и Романа.
- В разделе «Заявки» появились управление онлайн-заявками, подтверждение/предложение времени/отказ, справочник услуг и блокировка времени. Подтверждение только для двух менеджеров с дополнительным секретом.
- SMS только после подтверждения (через действующую очередь SigmaSMS) и напоминания за 24 и 2 часа, если до визита осталось достаточно времени. Google Calendar синхронизируется при подтверждении, отдельная кнопка повтора при сбое.
- После подтверждения клиент может открыть личную ссылку из экрана подачи заявки и запросить перенос/отмену. По соглашению другое время менеджер согласует **телефонным звонком**.
- Вложения R2: выбор до 15 фото/документов; шкала процентов, скорость, отмена и повтор частей после обрыва/обновления страницы (файл нужно выбрать повторно). Старые Google Drive файлы остаются в CRM.

## Перед началом

Не удаляйте старые версии сайта, данные Supabase или файлы Google Drive. Сделайте резервные копии сайта и Supabase; опробуйте новую версию на тестовом домене Pages, только затем переключайте рабочий сайт.

**Важно:** архив включает код, а не секреты и не готовую серверную инфраструктуру. Публичная форма намеренно закрыта до настройки обязательных переменных, загрузки SQL и публикации услуг. Это исключает ложную запись клиента в неработающий сервис.

## Шаг 1. База Supabase

В вашем **существующем** проекте Supabase откройте `SQL Editor` → `New query` и выполните **только** `supabase/booking_v1_migration.sql`. Не запускайте заново основной `supabase_schema.sql` на рабочей базе.

Миграция создаёт 5 новых таблиц, функции проверки свободного времени и индексы, добавляет триггер на новые/изменённые ручные записи. Не удаляет старые данные. SQL перед первым запуском желательно проверить на копии проекта. Для операции переноса, отмены и подтверждения используется атомарная блокировка на уровне БД. Триггер не даст занять третье место в том же направлении.

Встроенные услуги будут `published = false`, `duration_minutes = null`. В CRM потом задайте продолжительности и публикуйте только реально доступные услуги.

## Шаг 2. Cloudflare R2

Cloudflare Dashboard → **R2** → Create bucket: `solncanet-files` (Standard). Не делайте bucket публичным. У проекта Pages в **Settings → Bindings → Add → R2 bucket** укажите:

| Binding | Bucket |
|---|---|
| `FILES_BUCKET` | `solncanet-files` |

Если меняете переменные или binding, потребуется **новое развёртывание**. Браузер общается с Functions того же сайта; R2 используется только сервером, ключи доступа R2 в браузер не выдаются. Файлы передаются частями (через Pages Functions). Это не публичный URL и не неограниченное бесплатное хранилище: бесплатная квота Cloudflare R2 Standard составляет 10 ГБ-месяцев плюс лимиты операций; дополнительное хранение оплачивается.

Текущий код поддерживает до 15 файлов и ориентировочно до 600 ГБ на один файл при 64 МБ/часть; реальный максимальный размер зависит от лимитов запросов, Cloudflare и устройства. Форматы: JPG, PNG, WEBP, GIF, HEIC/HEIF, PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, TXT, RTF. Исполняемые файлы и видео сейчас исключены.

## Шаг 3. Переменные и секреты Pages

Добавьте в Pages → Settings → Variables and Secrets (или эквивалентном разделе вашего интерфейса) **для нужного окружения**. Значения — ваши, ничего из списка не нужно записывать в HTML/ZIP.

| Имя | Что указать |
|---|---|
| `SUPABASE_URL` | URL текущего Supabase-проекта |
| `SUPABASE_SECRET_KEY` | Секретный ключ с правами server/service role (как уже в CRM) |
| `BOOKING_TOKEN_SECRET` | новый случайный секрет, не менее 32 символов, для защищённых ссылок |
| `BOOKING_ADMIN_ACTION_KEY` | другой секрет, не менее 32 символов; Сергей и Роман вводят его при первом открытии панели управления записью |
| `BOOKING_SERGEY_PASSWORD` | **точно** такой же пароль, как при входе Сергея в существующую CRM |
| `BOOKING_ROMAN_PASSWORD` | пароль Романа из текущей CRM |
| `BOOKING_CRON_SECRET` | отдельный случайный секрет не менее 24 символов |
| `BOOKING_PRIVACY_URL` | рабочий HTTPS-адрес актуальной политики обработки персональных данных вашей компании |
| `BOOKING_SITE_URL` | полный URL сайта/тестового проекта, например `https://<ваш-проект>.pages.dev` (укажите фактический) |
| `TURNSTILE_SITE_KEY` | открытый site key вашего виджета Cloudflare Turnstile |
| `TURNSTILE_SECRET_KEY` | секретный ключ Turnstile, держать только в Pages Secrets |
| `BOOKING_TELEGRAM_BOT_TOKEN` | токен отдельного Telegram-бота от BotFather |
| `BOOKING_TELEGRAM_SERGEY_CHAT_ID` | ID личного чата Сергея с ботом |
| `BOOKING_TELEGRAM_ROMAN_CHAT_ID` | ID личного чата Романа с ботом |
| `SIGMA_API_TOKEN` | существующий рабочий токен SigmaSMS |
| `SIGMA_SENDER` | действующий согласованный отправитель SigmaSMS (`Solncanet`, если подтверждён в кабинете) |
| `GOOGLE_CALENDAR_SYNC_URL` | существующий URL `/exec` Apps Script календаря |
| `GOOGLE_CALENDAR_SYNC_TOKEN` | действующий токен календарной интеграции |

Создайте Turnstile-виджет для **фактического домена онлайн-записи** (и для тестового домена, если используете). **Токены и пароли нельзя присылать в чат или помещать в архив**, достаточно настроить их в Cloudflare.

### Telegram

Создайте бота через `@BotFather`. Сергей и Роман должны отдельно открыть этого бота и нажать **Start**. Получите ID их личных чатов безопасным способом через Telegram Bot API, укажите два ID в Secrets. Уведомление содержит номер заявки, тип, время и ссылку на карточку CRM, но не раскрывает телефон клиента в Telegram. Если Telegram временно не отвечает, запись **остаётся** в Supabase; повтор выполняется из очереди.

### SMS

Шаблоны для подтверждения и напоминаний должны соответствовать согласованным в вашем кабинете SigmaSMS. Существующий cron/SMS runner должен продолжать работать. Клиентская форма **не отправляет** SMS при создании заявки. Управляющая ссылка пока показывается клиенту после отправки, но **не включена** в SMS: для этого потребуется отдельно согласовать шаблон с переменным URL. Без этого клиент должен сохранить ссылку сразу при оформлении.

## Шаг 4. Публикация именно Cloudflare Pages Functions

ВНИМАНИЕ: нельзя просто перетащить ZIP в веб-интерфейс Cloudflare и ожидать работу `/booking-public`, `/booking-admin` и других функций. Панельная drag-and-drop загрузка статических файлов не компилирует каталог `functions/`.

Для проекта Pages с прямой загрузкой используйте **Wrangler** (Node.js необходим на вашем компьютере):

```powershell
# 1. Распакуйте ZIP в отдельную папку
cd C:\path\to\solncanet-booking

# 2. Войти в ваш аккаунт Cloudflare
npx wrangler login

# 3. Посмотреть точное имя проекта
npx wrangler pages project list

# 4. Из корня распакованного проекта опубликовать сайт + Functions
npx wrangler pages deploy . --project-name ИМЯ_ВАШЕГО_ПРОЕКТА
```

Для существующего Git-проекта Pages возможна другая схема публикации через Git, если там есть свой pipeline; главное, чтобы каталог `functions/` был обработан системой сборки Pages. Не меняйте адрес домена до проверки. Публикуйте сначала тестовый домен или preview.

## Шаг 5. Запустить планировщик

Нужен внешний планировщик (или Cloudflare Workers Cron Triggers), который **каждые 5 минут** обращается к:

`POST https://ВАШ_САЙТ/booking-cron`

HTTP заголовок: `Authorization: Bearer <значение BOOKING_CRON_SECRET>`.

Эта задача освобождает просроченные брони и повторяет неудачные Telegram-уведомления. Отдельно оставьте включённым действующий планировщик **SMS**. Не размещайте секрет в URL, открытом логе или публичной ссылке.

## Шаг 6. Включить услуги

Войти в существующую CRM под Сергеем или Романом → «Заявки» → «Онлайн-заявки с сайта» → «Услуги для сайта». При первом обращении менеджер вводит `BOOKING_ADMIN_ACTION_KEY` (не пароль CRM). По каждой услуге проверьте фактическую цену, задайте продолжительность, при необходимости шаг интервалов и включите «На сайте». Опубликуйте несколько услуг для тестирования; не включайте весь список без проверки.

Клиентская форма станет активна только после настройки обязательных переменных, R2 и опубликованных услуг. Она будет показывать сообщение о настройке вместо ложного подтверждения.

## Приёмочные испытания перед рабочим доменом

1. Откройте `/booking-public?mode=config`; JSON должен содержать `"ok":true`, `"ready":true`, непустой `services`. Если `ready:false`, ищите пропущенные переменные из шага 3.
2. Проверить на телефоне и ПК: выбор направления, услуги, даты, времени, формы, согласия и Turnstile.
3. Подать тестовую заявку. Она появляется в списке CRM со статусом «Ожидает подтверждения» и меткой «С сайта», приходят два личных Telegram-уведомления; **SMS не приходит**.
4. Открыть календарь; создать две одновременные записи в направлении «Авто», третья не должна выбрать тот же интервал; для «Архитектура» — независимые два места.
5. Подтвердить запись под Сергеем: создаётся SMS в очереди, появляется Google Calendar. Повторное подтверждение не должно создавать второе SMS/событие.
6. Проверить предложение другого времени, отказ, истечение 24 часов (тестируйте на отдельной заявке), блокировку рабочего времени и запрос переноса/отмены по сохранённой ссылке.
7. Загрузить фото и PDF в R2; проверить прогресс и повтор загрузки после обрыва связи, отображение файлов в нужной заявке.
8. Войти под ограниченным сотрудником и убедиться, что кнопок подтверждения нет, а прямой вызов `/booking-admin` без менеджерских секретов отклоняется.
9. Проверить, что **старые** заявки, другие разделы CRM, работа с прежними файлами Google Drive и существующие SMS функционируют как раньше.
10. Проверить, что публичная форма и серверное хранение персональных данных соответствуют применимому законодательству (включая локализацию персональных данных граждан РФ при необходимости).

**Ограничение проверки:** ZIP можно статически проверить на отсутствие JS-синтаксических ошибок, целостность файлов и корректность связей. Без ключей пользователя, рабочей базы, Telegram-бота, SMS-кабинета и Cloudflare R2 невозможно заявлять, что реальные уведомления/записи в продакшене уже проверены.

## Частые ошибки

- `Unexpected end of JSON input` или HTML вместо JSON — Pages Functions не развернуты. Используйте Wrangler.
- `Сначала выполните миграцию ...` — отсутствуют таблицы/функции `booking_v1_migration.sql`.
- `ready:false` — отсутствует одна из обязательных настроек или R2 binding.
- `Не удалось синхронизировать Google Calendar` — проверьте URL `/exec` и токен, затем нажмите «Синхр. Google» у подтверждённой заявки.
- Ошибка R2 — проверьте binding `FILES_BUCKET` и лимиты Cloudflare. Не делайте bucket публичным.
- Сергею/Роману не приходит Telegram — бот должен получить `/start` в каждом личном чате, проверьте ID чатов и cron.
